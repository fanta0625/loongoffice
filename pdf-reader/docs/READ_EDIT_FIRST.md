# 真实 PDF：只读阅读与按需编辑

## 本次交付

入口为 `tools/read_edit.py`，使用私有 Office 进程、profile 和源文件快照。原 PDF 不被写入。打开真实 PDF 后，通过 Office 内置 PDFium 图形导入建立阅读页面；页面图像放在锁定图层，并以原生 `ReadOnly=True` 打开文档。初始没有执行 PDF 到可编辑对象的转换，阅读时切页也不会转换。

界面使用 Draw 内的原生 UNO InfoBar，没有独立控制窗口。点击一次“编辑”（或工具栏的“编辑文档”），通过原生 `.uno:EditDoc` 解除只读，并确认仍为同一个文档对象。之后新页面停留约 350 毫秒会自动转换，不再逐页点击编辑；快速经过的页跳过，已转换页复用。转换失败保留预览，通过 InfoBar 的“重试当前页”重试，不在后台无限重试。当前不提供返回只读模式的切换。

仍是开发脚本入口，尚未打包成 OXT 菜单。当前使用 Draw 原生单页导航，不启用 `P0A1` 固定三页的连续画布实验；不能把这一版称为任意页连续编辑或瓦片阅读已经实现。滚动只有实际改变活动页时才触发页面观察，不能把它等同于连续画布的可见区调度。锁定图层防止普通选择预览，不是阻止所有编辑命令的权限机制。

模块分工：`reader_infobar.py` 负责原生 InfoBar、命令拦截和关闭通知；`edit_mode.py` 负责文档模式、页面停留和失败重试策略，不依赖 UNO 控件；`reader_session.py` 负责预览归属、指定页转换和对象替换事务。所有 UNO 操作在启动器主循环串行执行；350 毫秒等待只能跳过尚未开始的导入，不能中断已经执行的同步转换。

## 指定页转换

原有 `draw_pdf_import` / `XmlFilterAdaptor` 将 `FilterOptions` 传给内置 `xpdfimport`。新增选项 `Page=2`（严格的 1-based 单页编号），在辅助转换器调用 `displayPage()` / `processLinks()` 的循环前选择页；不是先整篇转换再删除其他页。旧的空选项和 `SkipImages` 行为保留。零、负数、越界、溢出和页范围表达式拒绝导入。该选项不与 `SkipImages` 组合。

`open_for_edit(..., page=n, hidden=True)` 创建暂存 Draw 文档；过滤器失败或返回不止一页会销毁暂存文档并报错。客户端页数检查能拒绝旧转换器的多页回退；必须运行下述原生检查，确认当前构建支持此选项。

编辑导入继续复用 Office 原有、基于内置 Poppler 辅助程序的**可编辑转换**管线；阅读渲染继续使用内置 PDFium，没有引入外部 Poppler 命令、MuPDF 或其他阅读引擎。

同一文件的解析、字体索引、字体资源处理仍可能发生；“指定页转换”不等于文件打开与字体成本已经按页隔离。阅读启动目前也会枚举全文页面并建立 PDF 图形，未做异步首屏、瓦片、缓存或取消。

## 替换事务与编辑状态

- 原预览一直保留到暂存单页导入与所有对象克隆成功。尺寸不一致、转换失败、克隆失败时，不删除阅读预览；中途插入的对象回滚。
- `SvxDrawPage::add()` 的跨模型分支克隆原生 `SdrObject`，不经过系统剪贴板，不重新定位到窗口中心。克隆对象及组内成员放入可编辑图层。
- 转换本身是不可撤销的基线切换。该段操作暂时锁定 UndoManager，不清空其他页的撤销记录；成功后的文字与对象修改使用 Draw 原生撤销重做。
- 已转换页再次请求编辑直接复用，切页不淘汰编辑模型，不用阅读 LRU 管理编辑对象。
- 原生窗口关闭和关闭文档命令接入会话：有修改先确认是否放弃，取消则保留窗口。当前拦截保存、另存为、保存副本及 PDF 导出命令，防止输出混合预览与编辑对象的未完成结果；不是完整的文档权限机制，也不承诺拦截第三方代码直接调用存储 API。尚无 PDF 保存入口，请用测试文件。

仅支持本地非加密 PDF 的初步功能验证。要求每个阅读页只有一个 PDFium 页面图形；有额外导入对象时拒绝继续。未适配的 CropBox / 旋转导致阅读与编辑尺寸不一致时拒绝替换。页面插入、删除、改名、重排不受支持；仅导航与内容编辑。删除、重排若撤销恢复，脚本仍不能据此保证源页身份映射。母版内容、表单、批注、签名、结构保存不在本次承诺范围。

## 目标机器运行

本次 InfoBar／文档模式更新只涉及 Python；已通过原生选页检查的现有构建直接运行，无需重编译或安装扩展。只有尚未构建过 `xpdfimport Page=n` 支持时，才在已有配置的源码根目录增量编译：

```bash
set -o pipefail
make PARALLELISM=4 build 2>&1 | tee ../pdf-page-edit-build.log
```

在图形桌面执行自动检查，使用支持选页的构建和对应 UNO 库：

```bash
(
    export PYTHONPATH="$PWD/instdir/program"
    export LD_LIBRARY_PATH="$PWD/instdir/program"
    export URE_BOOTSTRAP="vnd.sun.star.pathname:$PWD/instdir/program/fundamentalrc"
    timeout 180s python3 pdf-reader/tools/probe_page_edit.py \
        --office "$PWD/instdir/program/soffice" --panel-smoke
)
```

检查默认使用十页 PDF（可用 `--pages N` 调整，至少三页），覆盖每页实际文字对应关系、越界拒绝，以及同文档替换、暂存转换失败、克隆中途失败、重试、重复进入、修改保留和既有撤销历史不变。`--panel-smoke` 这一兼容参数现验证原生只读、InfoBar、实际 frame 编辑命令、页面停留后自动转换、关闭否决和保存命令拦截，不再创建独立面板。省略它则运行 headless 替换事务检查，不能据此声称图形模式切换通过。

### 预览对象归属检查

目标机曾在第 2 页编辑完成、进入第 3 页时报告预览名称为空、图层为 `layout`。这表示原有预览标记检查失败，不能据此判定用户修改过文档，也不能据此认定选页转换器失败。开发机旧版本回归未稳定复现该状态，底层触发原因尚未确认。

阅读初始化现在通过 UNO 显式创建会话持有的预览形状，直接使用原形状的内部 PDF Graphic 和几何尺寸，替换导入器创建的形状；不使用外部渲染器，不转换成 PNG，也不进行编辑导入。名称、锁定图层和对象身份在初始化完成后立即回读验证，编辑前及暂存导入后再次检查。检查失败仍然中止，绝不通过给未知图形补标记来绕过保护。错误信息包含页号和发生阶段。

自动检查额外验证每页预览均能通过内部图形服务渲染出不同图像，并确认冒用相同名称、图层的替换图形会在调用编辑导入器之前被拒绝。PNG 导出仅用于测试。这部分调整只涉及 Python，会话验证无需重新编译 Office；目标机需更新脚本后重新运行上面的原生检查，以确认是否消除该异常。

目标机随后在赋值 `Graphic` 时返回 `IllegalArgumentException`。源码中该 setter 要求非空 `XGraphic`，仅凭异常还不能区分空值和类型转换失败。初始化现先读取原对象的图形及几何数据，再创建／插入预览对象，并使用 `uno.invoke` 和显式 `uno.Any('com.sun.star.graphic.XGraphic', ...)` 赋值。若原图形为空，会在改变该页之前报告页号；不传入空值、不跳过预览、不回退到外部渲染器。开发机适配器回归通过，目标机兼容性仍需重新验证。

目标机三页原生检查通过后，真实十页 PDF 在第七页返回空 Graphic、空图层。审查发现初始化先通过临时 `page.getByIndex(0).getShapeType()` 检查类型，再重新获取原对象。`SdrObject::getUnoShape()` 使用弱引用缓存，`SvxShape` 析构时清除绑定，绑定失效后属性读取可以返回默认／空值。因此将临时包装对象的释放与重取列为重点嫌疑；现改为第一次获取即持有同一引用，类型检查和数据读取均使用它，不以等待、重试或外部渲染掩盖失败。该具体文件尚未在开发机复现，不能宣称根因已确认。开发机十页适配器图形会话检查（含十页不同预览、替换保护、失败回滚与历史保留）通过；仍需目标机原文件复测。失败报告现在保留错误类型和消息。

通过后，在图形桌面运行真实文件：

```bash

    export LD_LIBRARY_PATH="$PWD/instdir/program"
    export URE_BOOTSTRAP="vnd.sun.star.pathname:$PWD/instdir/program/fundamentalrc"
```

1. 启动显示 `editable imports so far: 0`；窗口内显示“PDF 阅读模式”InfoBar，没有浮动面板。文档处于只读，阅读时来回切页不出现编辑导入日志。
2. 选择第 2 页，点击一次“编辑”，停留后在相同窗口修改文字／对象；观察位置、字体、颜色、图片是否正确。
3. 切到尚未编辑的页，停留后应自动转换，不需要再次点按钮；快速翻过中间页，应只处理最终停留页。切回第 2 页，原修改与撤销重做仍正常。
4. 已编辑页直接复用；会话报告记录 `mode`、实际请求页号、失败与已编辑页。转换失败显示“重试当前页”，预览仍在。
5. 保存命令被禁用／拦截；关闭有修改的文档时先选择取消，确认窗口和修改保留，再关闭并确认放弃。确认原文件未被写入。

## 开发机验证边界

### 编辑对象显示／选择与窗口关闭

目标机日志已确认真实 PDF 第 1、2、3 等页生成了原生对象，但用户反馈不能交互编辑且翻页后有空白；仅凭对象数量不能确认 GUI 可用。源码中 `SdLayer::set()` 同时修改当前 `SdrPageView` 与 `FrameView`，因此不能只在隐藏初始化时设置一次。现每次观察活动页时校验并恢复会话自有预览／编辑图层的可见性和锁定状态，进入编辑及切页时激活编辑图层；进入编辑后恢复 Draw 原生选择工具。不解锁其他图层，不用重导入覆盖已有编辑。

新增检查主动隐藏、锁定编辑图层并切回锁定预览图层，再验证恢复后导入文本能通过原生控制器被选中。每次转换日志补充 `view` 状态（只读、活动图层及两个自有图层的可见／锁定状态）。本地适配器检查不能证明目标 PDF 空白的根因已确认；目标机仍需复测画面、鼠标编辑和返回先前页面。

关闭窗口时 `getCurrentController()` 可能先返回空值，早于关闭通知到达。现将这一状态识别为会话结束，正常清理并写报告，不再对空控制器调用 `getCurrentPage()`。独立回归覆盖该状态。

本次 15 项 Python 单测通过，WSLg 适配器检查验证图层恢复、原生文本选择和修改／撤销保留；实际启动脚本验证模式日志与转换后的可见／锁定状态。开发机不持有目标真实 PDF，不能把这些结果表述为该文件画面已修复。

### InfoBar 容器初始化兼容修复

目标机十页文件已完成阅读加载，但 `appendInfobar()` 抛出 `Could not create Infobar`，随后启动器清理窗口。这与 PDF 编辑导入无关。26.2.6 基线的 `SfxViewFrame::AppendInfoBar()` 在原生 InfoBar 子窗口尚未创建时直接返回空值，UNO 接口将其转为上述异常；本会话采用隐藏加载后显示窗口，不能假定此时子窗口已经初始化。

现在每次新增／重建提示条前，先调用原生 `.uno:InfoBar` 并显式传入 `InfoBar=True`，创建／启用容器，再使用原有 `XInfobarProvider` 添加按钮。不使用切换命令、延时重试或外部窗口替代，也不修改全局产品配置。此修复仅涉及 Python。图形检查先显式关闭容器，再验证初始化与阅读／编辑／重试提示条重建；目标机仍需更新后复测原文件。

目标机随后反馈上述显式命令仍不能创建 InfoBar，说明该修复不充分。继续审查 `SfxBaseController::ConnectSfxFrame_Impl()`：`IsMarkedHidden_Impl()` 分支会跳过正常路径的 `HideUI(false)`、dispatcher UI 更新、`Show()` 和视图激活。旧会话一直以 `Hidden=True` 加载，再只对顶层窗口 `setVisible(True)`，不能据此认定正常 UI 已初始化。

当前实现改为：用户阅读文档以 `Hidden=False, ReadOnly=True` 正常加载，并通过 `frame.activate()` 激活；不再通过显示隐藏窗口拼接 GUI 生命周期。只有 headless 会话及后台单页转换文档保持隐藏。这仍使用内部 PDFium，没有改为整篇编辑导入。新增单测检查两个加载入口的 Hidden／ReadOnly 参数，图形检查回读实际文档加载参数并验证 InfoBar、只读切换、图层恢复和原生选择。17 项 Python 单测通过，目标机仍须验证此次加载路径修复。
