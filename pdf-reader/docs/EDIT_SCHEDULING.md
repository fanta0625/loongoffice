# 按需编辑调度与相邻页暂存

本实现使用 Python 调度和 UNO，保持 LoongOffice 内部 PDF 导入／渲染引擎，不增加第三方引擎或后台线程 UNO 调用。

## 行为

- 阅读模式不准备编辑对象。点击编辑后，当前页停留 0.35 秒优先转换。
- 当前页完成后空闲两秒，按“后一页、前一页”顺序，每轮最多准备一页。
- 相邻页只导入隐藏暂存文档，不向用户页添加对象，不变更用户页的修改和撤销记录。实际切到该页时消费暂存文档，并沿用逐对象显示方式。
- 最多保存两页、合计 20000 个顶层 Shape 的暂存结果。Shape 数是粗略成本限额，不是内存字节上限；大图片或复杂组仍可能占用较多内存。超限结果丢弃。已经开始的导入仍有瞬时内存成本。
- 当前页转换时清理远处暂存结果。已编辑页面由 Draw 文档保留，不受暂存淘汰影响。退出时释放缓存文档。
- 复制每个顶层 Shape 前及移除预览前检查活动页。用户已切页时停止复制，移除本次未完成对象，保留预览和此前编辑，不强行跳回旧页。单个复杂 Shape 的原生复制仍不可中断。

## 真实限制

PDF 单页导入仍是同步调用，原生 `XmlFilterAdaptor::cancel()` 无实现。导入期间切页只能在调用返回后发现并丢弃过期结果；这不是立即抢占。相邻页的同步预取也可能延迟新当前页的处理，不承诺后台无阻塞。若文档单页转换很慢，运行 `read_edit.py` 时添加 `--no-prefetch` 可关闭预取。要实现导入阶段的真正中断，需要独立转换工作进程或原生取消链路。

复制阶段取消后本次部分对象全部回滚，不缓存半成品；回到该页时重新转换。用户只能依赖完成转换后的编辑结果；本版尚未支持转换中的对象并发编辑事务。

## 日志与验证

当前页结果新增 `cache_hit`、`import_seconds`、`copy_seconds`。`copy_seconds` 包含 UNO 复制、检查和引起的界面更新，不能当作纯绘制时间。预取记录 `prefetch-ready`、`prefetch-cancelled`、`prefetch-budget-skipped` 或 `prefetch-failed`，与用户实际编辑页记录分开。

目标机构建无需因本次 Python 修改重编译。拉取后继续运行原命令，检查：

1. 阅读中翻页无编辑导入；点击编辑并停留，出现当前页结果。
2. 等待相邻页 `prefetch-ready`，切到对应页，结果有 `cache_hit: true`，不再调用该页转换器。
3. 第 2 页对象逐个出现时跳到第 10 页，旧页取消并保留预览；返回后可以重新准备编辑。若仍处于 PDF 导入阶段，允许等待当前同步调用结束。
4. 第 2 页完成后修改文字，第 10→2 页返回仍保留修改和撤销；预取不把已有修改覆盖。
5. `--no-prefetch` 下只有当前页转换；关闭窗口后隐藏暂存文档一并释放。

自动检查：`python3 -m unittest discover -s pdf-reader/tests -p 'test_*.py'`。
目标机构建集成检查：`python3 pdf-reader/tools/probe_page_edit.py --office "$PWD/instdir/program/soffice" --panel-smoke --cold-import --pages 10`。
开发机若使用不含原生 Page= 适配的 Office，需要额外加 `--adapter-only`，其通过不能代替目标文件验证。
