# PDF Fast Linux 构建、功能及性能验证

日期：2026-11-13（日本时间；原始构建日志使用 UTC）。基线为 `f78aaa0f613fe1d76bff6f9e3b0d5ef2716d9543` 加工作区优化补丁。代码尚未提交。

## 结果

已在 WSL2 内的 ext4 源码工作区完成 Linux x86_64 release 构建。最终代码通过 134 项 CppUnit、3 项 Python 检查；三类合成 PDF 各重复 5 次，共 15 个 GUI 编辑／保存测试及 30 个直接启动测试（两种 PATH 各 15 次）全部通过。实现沿用原生 Draw 的同窗口、同模型只读／编辑切换，当前页按需转换为原生对象。

环境：Debian 13.1、WSL2 Linux 6.6.87.2、AMD Ryzen 5 5600X、WSL 内存约 15.6 GiB、GCC 14.2、GTK3/X11；GUI 为 Xvfb 1280×900×24，实际显示窗口，未使用 `--headless`。源码、对象文件和外部源码包缓存均在 Linux ext4。

- 实际 helper 持久会话、页 1／2／空白页、非法请求恢复、重复页输出一致及相邻命令行选项解析已验证。
- 默认完整导入与延迟单页导入的对象边界、位图校验对照；保留目标页尺寸、失败保留预览、跨页撤销、元数据克隆／保存屏障、区域快照 RGBA 像素对照已通过。
- 15 个 GUI 用例均确认 PDF 默认只读、切换后保持原窗口和模型、转换本身不标记修改、真实文本对象添加／删除／撤销、跨页首次准备、回访复用、编辑后返回只读，以及全部页面保存 ODG 后重开并保留编辑结果。

首次用户配置启动时，`javaldx` 会探测 Java。WSL 继承的 Windows PATH 包含大量 `/mnt/c` 目录，系统调用追踪显示它们被反复探测，拖慢程序启动。相同二进制、样本和新配置，仅将测试进程 PATH 设为 Linux 目录后，稳定首屏由约 18 秒降至约 2 秒；Java 仍启用。这属于启动环境修正，不能算成 PDF 渲染引擎的性能提升。另两次复用配置的无追踪诊断运行，首张 UI 图像观测为 1.244／1.162 秒，仅作定位证据，不参与上表统计。追踪运行含插桩开销，也不参与统计。

每个单项基于 5 个独立进程／用户配置；缩放汇总每类 25 次（100/150/200/75/100%）。直接启动测试使用携带 PDF 的 `soffice --draw` 命令，不配置或等待 UNO；每次计时前复制独立输入文件，防止前一测试强制退出遗留文档锁，因此该输入的文件缓存已受到复制影响。“稳定视口”在首页图像交付日志出现后通过截图稳定判断。首次图像交付的观测值也保存在 aggregate.json 中。

GUI 编辑测试采用先启动程序、连接 UNO、再打开 PDF 的自动化流程。进程启动到 UNO 可连接的独立统计为：文字 100 页 16.945 (16.817–18.388) 秒；矢量 30 页 17.024 (16.642–17.341) 秒；扫描 30 页 16.771 (16.561–17.063) 秒。该值不能直接当作用户携 PDF 启动的首屏耗时，也不能与上表两个不同流程的打开时间混为一谈。

截图稳定指标包含至少 200 ms 的观察窗口、轮询及调用开销，不能简单减去 200 ms 得到渲染时间；它不是 GPU 首帧或高清瓦片全部清晰的呈现追踪。编辑就绪来自原生对象准备完成日志；已准备页面重新进入编辑仅测调用／只读状态变化。内存为 50 ms 采样的进程族 RSS 相加，会重复计算共享页；全过程峰值包含全部转换、ODG 保存和重开。

## 实测发现并修正的问题

1. helper 删除命令行参数后继续递增索引，跳过相邻 `-f`／`-o` 等选项；修复移除后的迭代和缺值拒绝。
2. 临时原生导入文档沿用新建文档初始化，自动字距默认项造成可见排版漂移；改用原生导入的数据模型初始化，严格对象／位图对照通过。
3. `SetPixelOffset` 没有使缓存变换失效，区域快照偏移错误；补充失效并为裁剪边缘增加每侧 32 px 绘制余量。输出区域上限 1024×1024，内部缓冲上限 1088×1088。
4. 重复 GUI 测试发现后台解析成功后 UI 结果领取停顿；增加发布后的主动 UI 事件和关闭时的生产者 join／排队事件移除。通知晚于结果发布的断言及最终 15 个 GUI 用例通过；旧失败／调试数据保留但不参与统计。
5. 修正实际编译暴露的 FilterFactory 创建、完整类型、跨库导出和测试 API 兼容问题，最终完整构建与相关检查成功。

## 仍然存在的成本与验证边界

原生 XML／对象建立、对象克隆及编辑页快照仍有 UI 线程工作；复杂单页不会因异步 helper 自动变成零阻塞。普通 ODG 为保持脱离适配器后的完整可编辑性，保存时强制转换全部未准备页面，上表展示其时间和内存成本。异步预览、缓存及单页准备解决的范围不能覆盖这部分成本。

三份样本均为合成文件：文字 100 页、每页约 2400 个圆形的矢量 30 页、1240×1754 彩色扫描 30 页；文件大小和 SHA-256 见 samples/manifest.json。使用新进程／新配置，但没有清空操作系统文件缓存，因此不声称是完全磁盘冷启动。测试期间未并行运行编译或调试器，开启了 PDF Fast INFO 日志。

尚未做同机、同文件、同测量方法的 Okular 或原始提交 A/B，不能给出提升百分比或声称达到 Okular。尚未完成全部真实中文／加密／异常 PDF 矩阵、滚动呈现 P95/P99、ASan/TSAN，也不代表 Windows／龙芯构建已通过。
