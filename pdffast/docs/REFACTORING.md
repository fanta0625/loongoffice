# 原生改动收敛

本轮保留原生 Draw 的 PDF 文档控制器、后台瓦片预览、按页编辑，以及页面复制、保存、打印和导出的元数据／内容完整性屏障。

此前评审中复现的桌面入口问题仍需单独修复：加密 PDF 密码交互、`private:stream` 输入流，以及显式原生过滤器意图；本轮没有改变这些路由。

已转换页直接使用 Draw 原生绘制。旧区域快照接口 `PreviewRenderer::RenderRegion`、页面视觉版本计数及其专用测试不再属于产品路径，已移除；缩略图测试通过已有视图接触对象观察重绘失效，并继续检查预览交付、源对象身份、文档修改状态和撤销历史。旧 PDFium 图形打散器的专项诊断日志及其构建日志开关也已移除，当前编辑路径仍使用 Poppler/XML。

## VCL 修复

以下通用修复和测试都保留在当前功能分支：

1. 保留延迟 PDF 的页面几何，避免图形换出时在 UI 线程触发整页栅格化，并测试写时复制的首选尺寸以及普通／延迟元数据导入。
2. 像素偏移变化时使正／逆视图变换缓存失效，并直接测试两组缓存与偏移复位。

代码按 VCL 和 PDF Fast 的职责组织，不需要从其他分支 cherry-pick。

## 编辑门控

准备／失败状态同时需要页面视图级别的只读检查和命令级别的只读策略。`SdrModel::SetReadOnly` 是整个模型的状态，不能保证其他视图继续可编辑；`SfxDispatcher::SetSlotFilter` 是单一的可替换过滤器，已有幻灯片放映和文档过滤流程使用，也不能自动表达完整的原生只读命令策略。采用这两者直接替换会改变多视图或命令行为。

因此暂时保留现有的 `SdrPageView` 和 `SfxDispatcher` 视图级门控，但将字段、接口及其行为放进 PDF Fast 编译开关。关闭功能时不引入这些状态。集成测试检查一个视图准备页面时另一个视图没有被设为只读，以及取消、完成后门控恢复；命令和鼠标输入的真实窗口场景仍需平台回归。

后续若要完全移除公共接口，应先为可组合、可按视图释放的只读令牌建立上游通用协议，并测试现有 slot 过滤器、多个视图、切页和失败／关闭；不应通过全局模型只读或硬编码命令列表替代。

## 本轮验证

在 Debian 13 / WSL2 x86_64 release 验证构建副本中，启用 PDF Fast 后重编受公共头文件影响的库，并通过六个 CppUnit 目标：`sd_pdf_import_test` 11、`vcl_outdev` 61、`vcl_graphic_test` 89、`pdffast_core` 17、`pdffast_render` 5、`sdext_pdfimport` 16，共 199 项；日志汇总脚本另有 3 项 Python 测试通过。这些结果早于缩略图测试的观察范围增强；增强后的测试已通过启用配置语法编译，尚未完成运行验证。VCL 测试覆盖普通／延迟元数据导入。

通过 Xvfb / GTK3 的 500 页 PDF 窗口流程，包含 1 MB 图形缓存压力、预览和编辑模式连续跳页／缩放、编辑后往返页面。样本 SHA-256 为 `58ab727d3944df7506a298eaa1c8757f591cec828e9b1824930f92b448cef87c`；第 400 页转换为 5221 个对象，编辑就绪约 1169 ms。本次脚本观察到的最长 UNO 往返约 1849 ms，截图稳定时间和 UNO 往返是代理指标，不能代表物理呈现延迟或龙芯实机性能。

在同一 Debian 构建副本中通过 `--disable-loongoffice-pdf-fast` 重新配置后，已完整重编译并链接 `sfx2`、`svx` 和 `sd` 模块，`vcl_outdev` 测试通过。全产品构建及其他测试因依赖重建耗时而中止，关闭配置的窗口回归尚未执行。尚未执行 Windows、LoongArch / Qt6 及 ASan / TSAN 验证。
