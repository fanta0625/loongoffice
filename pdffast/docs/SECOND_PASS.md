# 第二轮阅读优化

本轮按“结果提交、过时任务中止、区域合并、预取与文件读取”实施。仅修改源码、编写回归用例并静态核对；没有编译、执行测试、启动 GUI 或测量性能。不能据此认定已经接近 Okular。原有十／十一项测试的历史验证不适用于本轮变更。

## 结果提交

[TransferBudget](../inc/transfer.hxx) 将每轮 UI 接收改为 4 ms 软预算，每转换一项后检查时间，最多 64 项。至少处理一项，避免永远无法前进。单块位图转换、布局更新、编辑快照及对话框不可中途打断，因此不是严格帧时限。

Session 每次交出一个拥有像素的结果。剩余结果仍受原有 16 MiB 队列预算约束；队列非空后续轮询为 1 ms、等待工作时 8 ms，空闲时停止。移除每 20 ms 最多两项的固定吞吐限制，保留背压。Timer 是调度请求，不保证操作系统按时回调。

## 协作取消与生命周期

[渐进渲染封装](../../vcl/source/pdf/PDFiumLibrary.cxx) 使用 PDFium Start／Continue／Close 和 IFSDK_PAUSE。关闭会话、整个合并区域都离开需求集合，或后台预取阻挡新可见任务时，回调要求暂停；调用返回后关闭渲染状态，丢弃未完成像素。仍需要的被抢占子任务放回队尾，过时子任务不重试。

关闭回调状态后才执行原有 FPDF_FFLDraw，保持表单外观行为；表单绘制前后再次检查取消。文档加载、页面解析、部分图片解码和表单绘制仍可能同步阻塞，没有任意时刻中断或最长延迟保证。返回部分像素、并行渲染和强制杀线程均未实现。

所有 PDFium 调用、页面／文档销毁及首次编辑的源冻结仍由 Source::engineMutex 串行保护。暂停回调只检查原子停止标记和需求集合，可获取 Session::m_mutex，不能重入 PDFium。锁顺序是 engineMutex → m_mutex；禁止反向持锁进入引擎。工作线程不创建 VCL 位图、不访问窗口，也不派发 UI 回调。输入回调不允许异常穿越 C ABI。PDFium 文档持有输入及回调资源，页面先于文档销毁。

## 有界区域合并

[Demand](../inc/demand.hxx) 只合并队首同页、同目标分辨率、同优先级且边缘相接的矩形，不跨越空洞，不合并整页预览或元数据。每次最多四个子任务，预取最多两个；区域宽最多 2048、高最多 1024、面积最多 1024² 像素。

每轮根据上一轮渲染及像素复制耗时调整子任务上限：超过 12 ms 或取消时退回一块，低于 4 ms 时允许四块，其余两块，初始两块。它只是保守启发式，不能把复杂页渲染限制在 12 ms 内，也不是性能测试结论。仅合并当前相邻队列项，不做全局矩形重排。

一次区域渲染完成后，按原子块相对区域的 x／y 偏移切出独立 BGR 缓冲。原 TileKey、需求去重、可见保护、预览保护和缓存成本均保留；发布前逐项核对需求。每轮仍最多缓存一个 PDFium 页面句柄；区域及拆分像素的临时内存有界，但不包含在 UI 位图缓存预算内。

## 预取

保留可见页沿滚动方向的一行视口外瓦片及两侧相邻页预览；进一步对滚动方向上的已知相邻页请求目标分辨率边缘行，仅覆盖当前水平视口。当前页额外瓦片最多八块，新增目标行在候选总数达到十二时停止，另一侧仍可追加一项元数据／预览；最终均使用可见工作集之外的剩余预算。未知邻页先查尺寸，不遍历整份文档。

预取优先级不参与身份比较，成为可见需求时可复用原任务与结果。预取不能侵占受保护的可见页预览预算；不因接收结果而循环补齐超预算清晰分块。暂未实现速度预测、整邻页高清预取或按结果完成自动链式推进。

## 源文件与编辑交接

[FileInput](../source/input.cxx) 持有一个源文件句柄，以 FPDF_LoadCustomDocument 随机读取。文件块为 64 KiB，独立 LRU 为 2 MiB；不由阅读器预先完整分配或复制源文件。PDFium 自身可能仍读取大量数据，尤其复杂索引或压缩对象流，因此不承诺只读首屏字节。空文件及超过 INT_MAX 的文件仍拒绝，未借此宣称支持大于 2 GiB 的编辑源。

文件句柄不启用 NoLock；读取及任务边界核对句柄长度、路径长度和修改时间。失败后不继续接收源数据。不能把这些检查当作不可变原子快照：不合作的同长度、同时间戳改写、检查之间的覆盖及文件系统差异仍需验证，必要时应改为明确的磁盘快照策略。每次回调的文件状态检查也可能增加 I/O 成本，须实测再优化。

首次编辑或导出在引擎锁内读取完整源字节，读取前后校验；成功后让同一输入对象改从该内存读取并关闭文件句柄。编辑 GfxLink 和阅读 PDFium 因此共用冻结后的数据，不按 URL 另读另一版本。分配／读取失败时不建立编辑器，导出入口捕获异常并保留现有阅读状态。这个完整读取仍在 UI 线程，首次编辑延迟和整文件内存成本并未消失。读取中检查失败的输入需重新打开恢复。

## 公共封装变更

基线封装只有内存 openDocument 与同步 renderPageBitmap。为避免在新模块直接暴露 PDFium 原始句柄，本轮在 [PDFiumLibrary.hxx](../../include/vcl/filter/PDFiumLibrary.hxx) 及对应实现新增 PDFiumInput 随机输入、openDocument 重载和 renderPageBitmapCancelable。原有调用仍走旧实现，Draw 导入器没有修改；模块仍默认关闭，但公共封装扩展随 VCL 构建，不受模块开关排除。

这是对“完全不改原业务 C++”目标的明确收缩。新增虚方法改变内部 C++ ABI，需要 VCL、可执行文件和编辑库同版本统一构建，不能将新模块与旧 VCL 混用。替代实现有默认降级入口，但不代表二进制兼容。尚未验证全部平台链接和模块关闭构建。

核对对象是本仓库 download.lst 指定的 pdfium-7471。API 依据：[该版本渐进渲染头文件](https://pdfium.googlesource.com/pdfium/+/chromium/7471/public/fpdf_progressive.h)、[该版本随机输入头文件](https://pdfium.googlesource.com/pdfium/+/chromium/7471/public/fpdfview.h)。external/pdfium 已列入 fpdf_progressive 源文件，无新增第三方依赖。

## 验证边界

新增三项核心测试源码：合并区域边界／分辨率／整页隔离，预取抢占后仍需任务重试与优先级身份，以及结果提交软预算／至少一项／数量上限。未执行这些用例；它们不覆盖真实像素裁剪、线程时序或文件回调。

后续需验证渐进与旧同步路径的像素对照（旋转页、表单、扫描页、透明与复杂矢量），渲染中快速跳页／反向滚动／关闭，合并区域右下边缘坐标，文件改写／删除／截断、密码重试及首次编辑／导出失败恢复。公共接口和新文件对象必须完成全量链接、模块开关两种构建及 GUI 验证。

性能对照使用同机、同 PDF、同 DPI、窗口及缩放，分别记录冷启动首屏、整屏清晰、快速跳页 P95、滚动 P95／P99 和峰值内存；日志耗时不等于屏幕呈现延迟。优先对比区域上限一块与自适应合并，确认合并减少调用成本而没有恶化取消响应。
