# 候选架构与决策记录

状态：初始候选架构记录。当前第一版源码选择了独立原生入口、PDFium 阅读、按源页隔离的 SdrView 编辑子窗及副本导出，具体实现与未覆盖范围见 [实现记录](IMPLEMENTATION.md)。下文保留其他候选及未完成的论证，不把它们视为都已实现。事实依据见 [接口审计](INTERFACE_AUDIT.md)。

## 1. 模块边界

建议以 `pdffast/` 承载新实现，保持阅读路径与 Draw 完整文档导入分离。解析服务模块只能提供部分组织参考；这里还需要窗口宿主、会话与编辑集成，不能仅注册一个导入过滤器就完成。

| 拟议组件 | 职责 | 不应承担的职责 |
| --- | --- | --- |
| 原生入口／路由适配 | 识别打开意图、必要 bootstrap、创建窗口和会话 | 先全量创建 Draw 页再决定是否阅读 |
| 阅读会话 | 稳定源版本、源页身份、任务代次、元数据、缓存预算 | 持有无明确生命周期的 UI 裸指针 |
| PDF 引擎适配 | 文档、按页访问、区域渲染、错误与密码 | 操作活动 Draw 模型或 UI |
| 原生视口宿主 | 连续布局、绘制、命中、缩放、滚动和 UI 输入 | 直接执行耗时 PDF 解析 |
| 编辑适配 | 延迟编辑环境、转换准备、资源校验、提交与撤销协调 | 把阅读缓存状态等同于用户编辑状态 |
| 保存协调 | 汇总源文件、修改页和目标格式策略 | 假定重输出 PDF 自动保留原结构与签名 |

纯调度和状态部分应尽量使用不依赖 VCL 窗口及 UNO 对象的结构；引擎、UI、SFX／Draw 依赖放在适配边界。内部服务创建可以使用进程内 UNO，无须为“去 UNO”绕过已有生命周期机制。

## 2. 启动集成的候选路线

| 路线 | 收益 | 尚需解决 |
| --- | --- | --- |
| 新模块内独立原生可执行入口 | 可验证最低启动依赖；无需先改 Desktop 业务流程 | 安装、关联、进程复用、用户配置与后续 Draw 环境 |
| 现有 Office 入口早期分流 | 统一用户入口与原进程体验 | 需要足够早且受控的路由钩子；过晚分流无法改善此前成本 |
| 仅通过 PDF 过滤器分流 | 接入位置现成 | 已经过文档和启动初始化，不能作为冷启动目标的完整答案 |

建议先用独立入口验证启动和显示成本，再单独审查产品入口集成。此顺序是调查策略，不代表最终决定采用两个应用。

每条路线都必须覆盖普通 PDF、混合 PDF、显式 Draw 导入、自动化与 headless 场景。新路径失败时是否回退、何时征求用户选择、如何避免循环路由，仍待产品和实现设计。

## 3. 两种生命周期分别管理

阅读状态可以从“未请求”进入“排队／执行／可显示／失败”。视口变化使请求过时，只影响其显示和缓存资格；不得顺带删除编辑模型。

编辑准备可以从“未准备”进入“准备中／待提交／可编辑／失败或取消”。用户修改与撤销历史是独立维度，至少记录用户修改修订，而不是以“已转换”为脏标记。

页记录需要稳定的源版本与源页编号，并映射到实际模型页。稀疏创建、删除或重排 Draw 页后，该映射仍必须正确。源页 ID、UI 位置和编辑模型下标不能混用。

缓存键至少要区分源版本、源页、缩放与区域、旋转及渲染策略。编辑后的显示还需要区分编辑修订；不能用原 PDF 缓存覆盖当前编辑结果。

## 4. 源版本与线程边界

稳定源必须先有一致性定义。候选包括保留稳定文件资源、创建快照或复制到自有存储；各方案都需要处理文件被覆盖、网络存储、密码和超大文件。完整复制可能影响首屏，延后复制又可能失去一致性，不能只通过异步化掩盖此取舍。

PDFium 的借用内存必须活到文档释放后；文档必须活到页及相关操作结束后。引擎操作的跨调用方线程协调尚未解决，不能先把“每页一个工作线程”写成架构前提。

UI 线程负责 VCL 窗口、Frame／控制器与活动绘图模型。后台工作只在其能力和线程约束明确后执行，向 UI 交接自有缓冲或隔离结果。事件携带会话、源版本和请求代次，提交前再次验证。

关闭时先使新请求和回调失效，再取消排队工作，等待不可中断的在途操作结束，最后按依赖顺序销毁引擎、模型和窗口相关资源。不能在释放文档后依靠“晚到结果会被忽略”保证安全。

## 5. 编辑宿主与转换路线分开选择

编辑宿主候选：

- 完整 Draw 模型／控制器：可复用较多现有工具和框架，但需要验证轻量进程中初始化、窗口所有权和混合画布嵌入。
- 原生 `SdrView` 宿主：底层接口较直接，但新模块需要适配命令、工具、输入法、剪贴板、可访问性和撤销上下文，不能视为完整 Draw 的等价替代。
- LOK 远端式编辑视图：已有分块和输入接口，但需要独立的模式／进程架构论证，当前不作为默认路线。

转换候选：

- `SdrEditView::DoImportMarkedMtf` 的 PDF 分支：复用现有指定页转换入口，重点验证字体全量预处理、保真、取消和撤销语义。
- sdext Poppler／SAX：重点验证是否值得增加选页和持久会话能力，以及暂存模型与目标页交接成本。基线尚不支持选页协议。

宿主和转换器是两项决策，不应因选定其中一项就假定另一项已解决。

## 6. 候选编辑交接协议

1. 绑定源版本与源页，保留当前可用阅读画面；避免同页重复准备。
2. 在隔离环境准备候选结果。若现有转换必须依赖活动视图／UI 线程，明确该限制，不伪装成纯后台函数。
3. 校验页面几何、字体、样式、图层及资源所有权，确定可提交范围。
4. 在 UI 线程核对会话仍有效、页映射未变化、请求未过时，再执行受控提交。
5. 协调撤销和修改状态；仅在提交成功后切换输入目标及显示权威来源。
6. 失败或取消时只回收当前请求拥有的资源，继续提供阅读或已编辑状态。

这是待实现的协议要求，不代表原有 `XImporter`、`Merge` 或转换进度回调已经提供原子性。若共享样式等无法可靠回滚，应在提交前隔离，或提出准确的公共接口缺口。

同一连续画布中的编辑页至少要验证裁剪、坐标转换、焦点、文本输入、鼠标捕获、滚动、缩放、工具激活、页切换和多页撤销。仅把编辑窗口叠到 PDF 位图上不构成完成。

## 7. 编译与运行隔离

已写入的开关：`--enable-loongoffice-pdf-fast`，默认关闭；Make 变量为 `ENABLE_LOONGOFFICE_PDF_FAST`。采用模块整体构建隔离，当前不需要在原业务 C++ 中新增宏分支。构建和安装仍待验证。

启用应由 LoongOffice 发行配置显式指定，并核对选定引擎和编辑后端依赖。关闭时不构建、不链接、不注册、不安装新功能目标与专有资源；启用时对普通文档也应保持延迟加载，避免无条件引入新启动成本。

需要分别审查 configure、生成配置、模块列表、库／可执行目标、组件注册、UI 和安装打包。基础配置改动不能混入原有文档行为变化；特性宏为 0／1 时按值判断。

任何共享核心修改都先说明：缺少哪个接口、调用前提是什么、为什么已有导出边界不可用、仅新增模块或独立入口是否可替代、功能关闭后是否完全不改变行为。
