# 需求与验收口径

状态：需求基线，尚无通过构建与运行验证的实现。源码能力见 [接口审计](INTERFACE_AUDIT.md)，候选设计见 [架构](ARCHITECTURE.md)，第一版覆盖情况见 [实现记录](IMPLEMENTATION.md)。

## 1. 目标

实现面向 PDF 的原生阅读路径，在阅读交互及冷启动首屏上以 Okular 为对照，同时支持按需进入 Draw 对象编辑。不能以打开空窗口、展示占位图或提前加载完整 Draw 模型代替目标达成。

性能数字尚未约定。先建立可重复的同条件测量口径，再确定具体阈值；不沿用历史实现的测试成绩或参数。

## 2. 已确认约束

| 编号 | 要求 | 对设计的约束 |
| --- | --- | --- |
| R1 | C++ 原生主路径 | 不依赖 Python、外部 UNO 进程或高频远程调用承担启动、显示、调度与编辑交接 |
| R2 | 独立 `pdffast` 模块 | 自有会话、视口和编辑适配层；优先复用已导出的底层能力 |
| R3 | 冷启动首屏 | 阅读模式不得先完整导入所有 PDF 页或初始化全部编辑 UI，才能显示实际内容 |
| R4 | 按需编辑 | 仅在编辑需求出现时准备对应页，避免整文档转换 |
| R5 | 同一窗口连续阅读与编辑 | 阅读页和已转换页的布局、坐标、焦点及输入需要统一管理 |
| R6 | 默认不影响原有流程 | 普通文档和未启用功能的构建继续使用原有路径 |
| R7 | 仅 LoongOffice 显式启用 | 编译开关默认关闭；不从产品名或 CPU 架构隐式推导 |
| R8 | 尽量不改原有业务源码 | 先验证现有宿主和导出接口；需要例外时列明最小改动及替代方案 |
| R9 | 保留编辑结果 | 不能因阅读缓存回收、切页、取消转换或页面重建丢失修改及撤销历史 |

R1 不要求移除 LibreOffice 内部的 UNO 体系。进程内服务创建、模型／控制器连接、VCL 窗口桥接可以作为集成手段。是否使用某个 UNO 接口，应由能力和调用成本决定。

## 3. 启动与路由

入口应同时识别文件类型和打开意图，不能只判断 `.pdf` 后缀。

| 场景 | 期望边界 |
| --- | --- |
| 合格的交互式 PDF 阅读 | 可进入新阅读路径；失败策略与提示需设计 |
| 用户显式选择原有 Draw PDF 导入 | 保留原有导入能力和明确入口 |
| 内含 ODF 的混合 PDF | 尊重原有检测与文档打开语义，不能抢先截获 |
| Writer／Calc／Impress／Draw 等普通文档 | 保持原有路由和启动依赖 |
| headless 转换、自动化、强制过滤器 | 不静默重定向到交互阅读器 |
| PDF 导出、打印、PDF 作为图片插入 | 不因新阅读模块改变原有语义 |
| 功能关闭的构建 | 不注册、安装或加载新路径所需的专有入口和资源 |

独立原生可执行入口有利于验证冷启动下界，但不能自动解决现有 Office 的文件菜单、最近文档、操作系统关联和进程转发。最终入口方案需要明确覆盖这些来源。

## 4. 阅读与编辑行为

阅读时优先显示当前视口，滚动和缩放后淘汰过时请求；缓存和预取策略受内存预算约束。页面尺寸、链接、批注、文本等元数据应区分首屏必要数据与可延后数据，不能把全量扫描藏在首屏前置步骤中。

源 PDF 页使用稳定身份，不依赖稀疏 Draw 模型中的页面序号。显示坐标必须考虑 PDF 页框、旋转、裁剪、缩放、DPI、滚动与编辑器单位。

编辑准备期间继续显示可用阅读内容。完成转换后通过受控交接激活编辑页；失败、取消或过时结果不得破坏其他页和已有用户修改。转换完成与用户实际修改是不同状态，单纯准备编辑页不应把文档标为已修改。

编辑触发手势、是否自动转换停留页、工具集范围尚未确定；这里不把任何历史交互策略作为默认实现。搜索、选字、表单、批注等阅读能力也应单独定义范围，不因已经能画位图而视为完成。

## 5. 数据与生命周期

- 解析、渲染、转换和缓存必须绑定同一个稳定源版本。选择文件句柄、快照或复制方案时，应同时评估首屏开销及源文件被覆盖时的行为。
- 仅把复制或哈希任务移到后台，不能保证其他任务读取的原文件没有变化。
- 文件内存、文档、页、位图、字体、编辑模型与 UI 的所有权必须明确；关闭窗口后不得继续回调失效对象。
- PDF 密码、损坏文件、读取失败、资源不足及不支持内容必须有可恢复的状态和退出路径。
- 保存必须区分“保留原 PDF 结构”和“将 Draw 编辑页重新输出”为 PDF 的差别；签名、表单、链接、批注等保真要求尚待确认。

## 6. 性能验收定义

| 指标 | 计时／观察边界 |
| --- | --- |
| 进程冷启动首屏 | 无目标进程时发起打开，到实际 PDF 首屏内容可见且 UI 可响应输入 |
| 视口响应 | 滚动／缩放／跳页输入，到对应可见区域获得可用内容及清晰内容，分别记录 |
| 编辑交接 | 请求编辑某源页，到对应页可操作；区分首次初始化编辑器和后续页转换 |
| 内存 | 阅读稳态、快速跳页、连续编辑、缓存淘汰后的进程及缓存占用 |
| 关闭 | 关闭请求到后台任务和相关资源释放；检查死锁、悬空回调和数据丢失 |

对照 Okular 时固定机器、PDF、版本、构建类型、窗口大小、DPI、缩放、页面位置和配置。分别记录进程冷启动、系统文件缓存状态以及首次创建用户配置的额外开销，不能用常驻进程或预热结果声称冷启动达标。

阅读渲染和 Draw 对象转换是不同任务。Okular 的阅读速度不能直接作为对象转换时延的证明，也不能仅凭相似架构推断性能一致。

## 7. 当前执行范围

初次任务完成静态调查与文档持久化；随后按用户要求编写第一版源码，继续遵守“不编译、不启动程序”的约束。没有运行功能测试或性能测试；后续计划中的这些项目均为待执行事项。
