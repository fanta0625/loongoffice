## 2. P1 的三个验证问题

### 2.1 启动和显示

沿 `minvcl` 类似的必要启动链，明确组件上下文、VCL、配置和字体初始化依赖。验证持久 PDFium 文档加小位图偏移渲染是否能正确显示首屏，而不经过 `ImportPDFUnloaded` 的全页处理。

记录首屏之前的完整文件读取、页枚举与库加载，不能只报告渲染函数的耗时。明确已有 Office 入口和独立入口各自的成本边界。

### 2.2 编辑宿主

分别调查完整 Frame／控制器与原生 `SdrView` 的依赖和导出符号。验证容器窗口生命周期、活动页、焦点、文本输入和命令路由，再判断同一连续画布是否可行。

建立“必需接口／声明位置／导出标记／调用线程／所有权／可替代方式”表。不要通过包含内部头文件或扩大链接依赖，掩盖实际 ABI 缺口。

### 2.3 单页转换与交接

优先验证基线已有 `DoImportMarkedMtf` PDF 分支，记录字体缓存冷态是否导致全页扫描。若考虑 Poppler 路线，先说明选页和持久会话需要新增哪些能力。

使用隔离结果验证提交、取消、样式冲突、撤销及重复请求。不能把“看见对象了”作为编辑事务正确的唯一证据。

## 3. 后续回归矩阵

以下为未来验证范围，本次没有运行这些检查。

| 范围 | 关键场景 | 需要证明 |
| --- | --- | --- |
| 功能关闭构建 | 新入口、组件、UI、依赖和安装清单 | 不构建／加载新路径；原流程不受行为影响 |
| 启用但非 PDF | 各类普通文档、启动中心和文件菜单 | 不误路由、不额外初始化新重依赖 |
| PDF 路由 | 普通、混合 PDF、强制 Draw、大小写／无扩展名 | 类型和意图识别正确 |
| 自动化 | headless、转换、指定过滤器、PDF 导出 | 保持原有非交互语义 |
| 原有 PDF 用途 | Draw 导入、PDF 图片插入、打印、导出 | 原能力及结果未被阅读路径覆盖 |
| 输入和格式 | 密码、损坏、扫描件、复杂字体、透明度、旋转和裁剪页 | 错误可恢复，显示与编辑保真可解释 |
| 调度 | 快速滚动、缩放、跳页、重复请求、关闭中渲染 | UI 响应、过时结果不覆盖、无资源越界 |
| 源文件 | 读取中改写、覆盖、删除、网络路径 | 各阶段使用一致源版本，错误处理明确 |
| 编辑 | 稀疏页、切页、重复转换、取消后重试、样式同名 | 源页映射与事务资源归属正确 |
| 修改状态 | 转换、实际编辑、撤销／重做、缓存淘汰、关闭 | 不误标脏，不丢失修改和撤销历史 |
| 视口与输入 | DPI、缩放、滚动、输入法、捕获、工具和快捷键 | 混合显示与命中坐标、焦点一致 |
| 并发 | 与现有 PDF 功能同时工作、多个文档 | 引擎线程约束及全局资源协调正确 |
| 保存 | 原页与编辑页混合、取消／失败、重新打开 | 不静默丢页或损坏原文件；保留范围明确 |

用最小有意义的样例覆盖错误边界，再结合已有相关测试；不为简单包装函数机械增加与实现同构的测试。后续编译、运行和基准验证不属于当前静态审查任务的执行范围。

## 4. 性能实验记录格式

每次实验记录版本提交、构建配置、机器、操作系统、配置目录、样本标识、页数、大小、DPI、窗口、缩放、缓存状态及重复次数。

分别记录进程启动、必要环境初始化、源数据准备、PDF 打开、首屏元数据、首屏渲染和首屏可交互时刻；给出用户观察到的总耗时。首次编辑另列环境初始化、字体准备、转换、交接和可操作时间。

同条件比较新模块、原有路径和 Okular。报告分布、峰值内存和错误情况，不以单次最好成绩下结论。当前尚无采样结果，不预设缓存容量、分块尺寸或固定延时常数。

## 5. 风险与应对

| 风险 | 优先调查／缓解方向 |
| --- | --- |
| 阅读首屏仍被全文件工作拖慢 | 分解读取、元数据、字体与配置开销；验证稳定源方案的代价 |
| PDFium 与其他 Office 功能并发冲突 | 明确全进程协调或隔离设计；模块内部锁不能代表全局安全 |
| 编辑器不能作为页内控件使用 | P1 提前验证宿主；必要时记录确切缺口而非依赖私有方法 |
| 转换保真和首次编辑成本不可接受 | 同样本对比两条转换路线，独立记录字体冷态成本 |
| 中途失败污染共享样式和页面 | 隔离准备、资源归属、受控提交；验证回滚只影响当前请求 |
| 保存损失原 PDF 特性 | 先明确保留目标和格式语义，再决定协调和输出策略 |
| 开关不彻底或非 PDF 启动变慢 | 同时检查目标、注册、UI、安装和延迟加载链 |
| 为零改动牺牲必要能力或过度改共享核心 | 逐项证明接口缺口，比较模块内方案、独立入口和最小公共接口 |
