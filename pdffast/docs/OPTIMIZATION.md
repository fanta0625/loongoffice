# 第一轮调度和显示优化

本文保留第一轮实施记录。第二轮已替换其中同步渲染取消、固定数量 UI 接收、首屏完整读取和邻页预取策略；当前实现参见 [第二轮优化](SECOND_PASS.md)。

状态：本轮仅修改和静态核对源码；未编译、未运行 CppUnit／GUI，未进行性能测量。保留独立进程和单渲染线程，不改原 PDF 导入器或其他 Office 业务路径。

## 请求身份与优先级

[Demand](../inc/demand.hxx) 使用“源页＋目标页像素尺寸＋瓦片区域”标识渲染请求，元数据使用同页的零尺寸键。Session 是文件级边界，不用每次视口刷新递增代次。

刷新时只重建未开始任务的优先顺序。仍被需要的在途请求和结果队列项保留，不重复排队；离开需求集合的结果被清理。在途同步调用只能等待完成，完成时再次核对需求集合；离开后又返回同一瓦片，也可接收仍在生成的结果。已上传的图像由 UI 缓存负责，刷新时不再请求。队列更新、完成身份释放和结果入队使用同一互斥锁，避免完成时重新排队的竞态。

需求顺序为当前可见页的元数据、预览及高清瓦片，然后才是预取。当前结果队列保留 FIFO 顺序，已开始的低优先级任务不会被新可见请求抢占；尚未实现引擎中止或优先级抢占。

## 有限预取

可见页中沿滚动方向预取紧邻视口外的一行瓦片，跨页合计最多八块；另外请求可见页集合两侧各一页的元数据或小预览，优先滚动方向。预取和可见内容共享原有图像缓存与 16 MiB 像素结果队列，没有另建无预算缓存。当前可见预览和瓦片（含尚未到达的结果）会预留预算；预取排队只使用剩余空间，结果入缓存时再次校验，拒绝会侵占可见预算的项。预取项优先淘汰，访问新近性不能提升它们超过可见项。预取结果不会触发邻页链式枚举。若可见工作集本身超过预算，维持硬上限并允许部分高清缺失，不反复自动排队造成渲染循环。可见页预览使用更高一级保护：清晰分块不能淘汰它们，而且为尚未到达的预览保留容量，必要时拒收清晰分块；离开视口即释放该保护。该保证要求所有可见预览自身能够容纳在预算内；极端页面几何使预览总量也超限时，仍需后续实现自适应预览尺寸。

连续缩放期间暂停高清及邻页预取，只保留必要预览。当前方向取自滚动位置变化，没有速度估计、耗时反馈或动态扩大预取距离。每个预取仍是不可中止的同步任务，因此复杂页可能延迟随后到来的可见任务；数量上限不是耗时保证。

## 缩放过渡

先检查当前分辨率的可见瓦片覆盖，仅在缺口内画预览及同页最接近的一档旧尺寸瓦片；绘制裁剪到视口内真实缺口。已齐备区域直接绘制当前瓦片。覆盖完整后不再检索、绘制或提升旧瓦片和预览的 LRU 顺序。旧瓦片即使只有部分区域，也可用于过渡；它们继续受同一个 LRU 预算约束，不保证一直驻留。不同文件和编辑后模型不会混用这些原始 PDF 瓦片。

连续缩放重新启动 80 ms 的静置定时器，在静置前不排新尺寸高清任务，静置后按最终视口请求。80 ms 是初始参数，没有实测依据。旧清晰瓦片暂时放大并不增加真实细节；新瓦片到达后才获得当前尺寸清晰度。

## 页面句柄与 UI 接收

工作线程最多保留一个 PDFium 页句柄，同页预览与瓦片复用它；换页时释放，页先于文档销毁。创建、渲染与销毁继续使用同一引擎锁，没有引入并发 PDFium 访问。后端仍会对每个瓦片执行渲染，没有实现区域合并，也没有减少像素缓冲到 VCL Bitmap 的复制。

每次 UI Timer 回调最多上传两块位图，剩余结果保留并继续施加队列背压。这是数量限制，并非严格的 16.7 ms 耗时上限：单次设备分配、转换、元数据处理和绘制仍可能超时。后续应根据实测决定时间预算和自适应批量。

## 编辑页的阅读快照

编辑库内部增加共享 32 MiB LRU。快照键包括源页、内容 epoch 和快照像素尺寸，单张最长边限制为 2048 像素；该预算在阅读瓦片预算之外，不包含模型、源数据或引擎内存。快照淘汰只丢图像，不丢编辑对象或撤销历史。

模型通过 SfxListener 通知使对应页快照失效；输入处理、撤销和结束文本编辑另做保守失效，epoch 不等于用户修改次数。阅读滚轮、平移和单纯窗口裁剪变化不会递增内容 epoch。缩放静置前可复用同 epoch 的已有快照，静置后补目标尺寸。

快照首次生成仍在 UI 线程调用 SdrView，完成后滚动重绘只绘制位图。创建失败时回退到模型重绘，不用原始 PDF 覆盖编辑结果。首次快照或淘汰后重新生成仍可能卡顿；大倍率下 2048 像素上限会损失细节，后续应考虑带时间预算的模型分块快照。首次转换的全文件字体收集问题也没有解决。

## 预取保护和过渡绘制评审修复

新增测试源码覆盖 16 MiB／15 块可见瓦片及预览的缓存压力、在途可见结果预算预留、预取优先淘汰、切换视口释放保护和超预算边界；另覆盖跨分辨率缺口相交、边界不相交、跨页隔离、覆盖完整时无回退项及只检查覆盖不改变 LRU。

用户报告前一提交 reader／session／editor GCC 语法检查及八项独立核心 CppUnit 通过，另复现了预取淘汰问题。这是修复前版本的外部验证记录。本次修复只核对源码、接口声明、文档引用和 Git 差异，没有自行编译、执行新增用例或做 GUI／性能测量。

后续用户核对预取保护和完整覆盖后跳过旧图绘制均符合预期，16 MiB 复现的可见瓦片缺失数降为 0；十项核心测试中九项通过，超预算用例因将实际成本为 4 的驻留项声明成 20 而失败。现将该用例改为驻留项 `{4, 4}` 加尚未驻留项 `{7, 9}`，总需求 13 超过预算 12，保持单项成本一致；同时断言拒绝预取后驻留项仍在、被拒项未加入且未超预算。此次仅修正测试，未自行重新执行；不能将先前九项通过视作修正后十项全部通过。

## 编辑宿主回调的生命周期修复

用户通过源码调用链发现，编辑页 Ctrl+O 调用宿主后会切换文件并销毁旧编辑器，原键盘处理随后仍调用 notify，访问已经销毁的快照缓存及旧编辑器回调。现将只读输入、空闲 Esc、宿主快捷键和未处理按键的转交统一为调用后立即返回，不再对旧页面做后处理。转交前复制 std::function，使回调自身不随页面成员一起销毁；滚轮／命令转交也采用局部回调副本，随后立即返回。

此次检查了编辑页的 key／command／changed 回调调用点；修改通知仍只调用宿主标题更新。未运行 GUI 或 ASan，纯布局／缓存测试不能证明这一窗口生命周期场景。后续需验证：F2 后不修改直接 Ctrl+O 切换、修改后选择丢弃／导出／取消、只读模式转交 Ctrl+O、选文件后打开失败，以及 Esc、缩放与撤销仍正常工作。

## 超预算时保留页面预览

用户用真实缓存类独立复现：16 MiB、4K 视口、A4 300% 的可见清晰分块超预算时，普通保护项的淘汰路径也会删掉页面预览，导致缺块区域持续空白。原有十项核心测试通过，并未覆盖这一分级需求。

本次为 Cache::protect 增加可见预览集合，区分“可见清晰分块可降级”和“页面预览须保留”。清晰分块入缓存前核对其他预览的总预留，放不下则拒绝，且拒绝前不改动已有条目；尚未到达的预览容量也计入预留。淘汰遍历始终跳过当前可见预览，预算仍为硬上限，不增加按结果循环重试的调度。

新增回归测试源码模拟 16 MiB、25 块清晰瓦片及预览的逐批入缓存与绘制访问顺序，验证高清出现缺口时预览仍驻留；还覆盖多页预览后到达、拒收超容量分块，以及切换视口后允许淘汰旧预览。本次只做静态核对，没有编译、执行新增用例、GUI 或导出验证；先前测试通过记录不代表修复后的测试已执行。
